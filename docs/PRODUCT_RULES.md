# REVIXA PRODUCT RULES

Governance rules for business logic, metric definitions, and AI narrative structures.

## 1. Single Business Question Rule
Every page in Revixa must answer exactly **ONE** core business question. Components on a page that do not contribute to answering its core question must be removed.

| Page Route | Core Business Question |
| :--- | :--- |
| `/dashboard` | **What happened in my business today?** |
| `/insights` | **Why did it happen?** |
| `/forecast` | **What will happen next?** |
| `/marketing` | **Which ad campaign caused it?** |
| `/products` | **Which SKU caused it?** |
| `/customers` | **Which customer cohort caused it?** |
| `/settings` | **How is Revixa configured?** |

---

## 2. Single Source of Truth Rule
- Every business metric (Revenue, Orders, Conversion Rate, Inventory Days, Stockout Loss) has exactly **ONE** origin: the `mock-api.js` service layer.
- Components must NEVER recalculate or hardcode business metrics independently. UI components only render data provided by `app-store.js`.

---

## 3. Signature 6-Step AI Narrative Rule
Every AI Insight generated by Revixa must strictly follow this 6-step structure:

1. **Observation**: Plain-English statement of what changed in the business.
2. **Root Cause**: The underlying driver (targeting shift, speed gain, script issue).
3. **Evidence**: Cross-channel telemetry confirmation pills.
4. **Recommendation**: Specific, actionable operational instruction.
5. **Expected Business Impact**: Quantified financial gain or loss prevented.
6. **Confidence Score**: Statistical confidence rating (e.g., `96.2% Causal Confidence`).

---

## 4. UI Restraint Principles
- **No Decorative Noise**: Remove status badges ("Healthy", "Live") unless they require user action.
- **Whitespace First**: Use whitespace and typography hierarchy instead of extra containers or decorative borders.
- **Explanation Over Visualization**: Prefer plain-English narrative synthesis over complex multi-axis charts.
